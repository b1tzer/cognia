# Cognia 五态认知状态转移矩阵（State Machine）

> 本文档定义 Cognia 的核心状态机——五种认知状态之间「哪些转换允许、需要什么证据、哪些禁止」。
> 它是 spec v2.0 §2 五态定义与 plan §3 状态机设计的领域核心，被 spec 与 plan 共同引用。
> 状态迁移的统一前提：所有迁移都要求「高置信度」（中 / 低置信度一律不迁移，见 clarifications Q4）。

## 1. 状态转移总览

关键前提：

- `unassessed` 是唯一「初始态」。
- `mastered` **不是终态**，可被降级（跨会话「旧 mastered 后来发现不会了」）。
- **`mastered` 是「最终状态迁移的结果」，不是单次 `diagnose` 的直接产物**：`diagnose` 可判断「当前表现看起来达到 mastered」，但不能直接完成迁移；任何进入 `mastered` 的迁移都必须先完成「概念解释 + 场景辨析」双重验证，由纯逻辑规则确认后方可迁移。

| 源态 ╲ 目标态 | unassessed | unknown | partial | misconception | mastered |
|---|---|---|---|---|---|
| **unassessed** | — | ✅ 首次诊断 | ✅ 首次诊断 | ✅ 首次诊断 | ✅ 首次诊断 |
| **unknown** | ❌ | — | ✅ 教学后 | ❌ 禁止 | ✅ 教学后 |
| **partial** | ❌ | ❌ 禁止 | — | ✅ 深入探测 | ✅ 补全后 |
| **misconception** | ❌ | ❌ 禁止 | ✅ 纠错后 | — | ✅ 纠错后 |
| **mastered** | ❌ | ✅ 降级(罕见) | ✅ 降级 | ✅ 降级 | — |

> 图例：✅ 允许（需证据）｜❌ 禁止｜— 无意义（自我迁移不算转换）

## 2. 各「允许转换」的触发条件与所需证据

### 2.1 unassessed → 各态（首次诊断，四选一）

| 目标态 | 触发 | 证据要求 |
|--------|------|---------|
| `unknown` | 用户明确否定 | 原话「我不知道 / 没听过 / 没接触过」（否定证据） |
| `partial` | 能说大意但细节模糊 | 原话正确但不完整、边界说不清 |
| `misconception` | 表达有逻辑错误且自认正确 | 原话存在概念混淆、因果倒置等硬伤 |
| `mastered` | 双重验证全过 | 概念解释 ✅ + 场景辨析 ✅（两份独立正向证据） |

### 2.2 unknown → partial / mastered（教学后）

| 目标态 | 触发 | 证据 |
|--------|------|------|
| `partial` | 解释干预后能复述大意 | 用户能用自己的话说出核心，但细节仍不全 |
| `mastered` | 解释干预后双重验证全过 | 概念解释 ✅ + 场景辨析 ✅ |

### 2.3 partial → mastered / misconception

| 目标态 | 触发 | 证据 |
|--------|------|------|
| `mastered` | 补全后双重验证全过 | 概念解释 ✅ + 场景辨析 ✅ |
| `misconception` | 深入探测发现根子错了（非细节模糊） | 核心机制理解错误 |

### 2.4 misconception → partial / mastered（纠错后）

| 目标态 | 触发 | 证据 |
|--------|------|------|
| `partial` | 颠覆型纠错后承认错误但新理解不全 | 用户接受纠正，但复述仍不完整 |
| `mastered` | 颠覆型纠错后双重验证全过 | 概念解释 ✅ + 场景辨析 ✅ |

### 2.5 mastered → partial / misconception / unknown（降级）

降级只由「新的诊断证据」触发，绝不凭空降级。**mastered 的降级同样遵循高置信度原则；涉及 misconception 的降级必须存在明确的核心机制错误证据，不能仅凭细节错误或一次表达异常降级**（防止长期认知状态抖动）。

| 目标态 | 触发场景 | 证据 |
|--------|---------|------|
| `partial` | 该知识点作为新目标的前置依赖被检验时，暴露细节遗忘 | 用户复述模糊、边界不清 |
| `misconception` | 复习 / 依赖检验时暴露**新的核心机制错误** | 用户表达出现明确的逻辑硬伤，不能仅凭细节错误或一次表达异常降级 |
| `unknown` | 用户明确表示「完全不记得了」（罕见） | 否定证据 |

## 3. 禁止转换及理由

| 禁止转换 | 理由 |
|---------|------|
| `unknown → misconception` | unknown 是「确认不知道」，系统会主动教正确内容，不会教出错误理解；若用户带外部错误认知回来，属新输入，应重新走 `unassessed → misconception` |
| `partial → unknown` | 部分掌握不会倒退为「完全不知道」；若用户明确否定，说明之前诊断有误，属重新评估 |
| `misconception → unknown` | 错误理解不会变「完全不知道」 |
| `mastered → unassessed` | 已掌握不会变回「从未评估」 |
| 一切「中 / 低置信度」下的迁移 | 证据不足，禁止迁移状态（见 §5 通用规则） |

## 4. 跨会话状态更新规则

1. **mastered 非终态**：任何后续会话中，只要该知识点被重新检验（作为前置依赖、或用户主动提及），就有机会被降级。
2. **降级必须走证据链**：不允许「时间久了自动降级」，必须有新的用户原话证据支撑。
3. **降级同样记录 Delta**：`from_state=mastered → to_state=partial` + evidence + timestamp。
4. **MVP 不引入主动复习**：降级主要发生在「前置依赖塌方」场景（对应 clarifications Q5 的跳转机制），主动定期复习留待北极星验证后。

## 5. 通用规则（所有转换统一约束）

1. **诊断（Diagnosis）是候选，状态迁移（Proficiency）是裁决**：`diagnosis.state` 只是「候选状态」，绝不直接写入长期 Proficiency；必须经「置信度验证（高置信度）+ `can_transition()` 状态机判断」双重闸门后，才允许产生 Proficiency Delta。任何 `proficiency[point_id] = diagnosis.state` 的直写都是旁路，属违规。
2. **高置信度是唯一迁移门槛**：中置信度「原地冻结 + 追加探针」，低置信度「不改变状态 + 继续探测」，两者都不迁移状态（clarifications Q4）。
3. **证据必须来自用户原话**：严禁 AI 脑补；未提及知识点一律 `unassessed`（spec §6）。
4. **每次迁移都要落 ProficiencyEntry**：携带 `from_state → to_state + evidence + timestamp`，增量 Delta，严禁全量重写（宪法 §5）。
